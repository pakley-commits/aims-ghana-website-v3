# Wasmer Deployment

This Hugo site deploys to Wasmer Edge as a static website. Hugo builds the site into `public/`, then Wasmer packages that folder and serves it with `wasmer/static-web-server`.

## One-Time Wasmer Setup

1. Install the Wasmer CLI on Windows:

   ```powershell
   iwr https://win.wasmer.io -useb | iex
   ```

2. Restart PowerShell so `wasmer` is on your PATH.

3. Log in:

   ```powershell
   wasmer login
   ```

4. If your Wasmer username or namespace is not `leuma`, replace `leuma` in:

   - `app.yaml`
   - `wasmer.toml`

## Build And Deploy

Use the final Wasmer app URL as Hugo's base URL before deployment. With the current config, the expected URL is:

```text
https://aims-ghana-website-leuma.wasmer.app/
```

Build:

```powershell
hugo --gc --minify --buildDrafts --buildExpired --buildFuture --forceSyncStatic --baseURL "https://aims-ghana-website-leuma.wasmer.app/"
```

Deploy:

```powershell
wasmer deploy
```

Wasmer will publish the package from `wasmer.toml`, then deploy the app from `app.yaml`.

## Wasmer Dashboard Settings

Use these values if the Wasmer dashboard asks for app settings:

```yaml
Owner / namespace: leuma
App name: aims-ghana-website
Package: leuma/aims-ghana-website
Entrypoint / command: script
Static output folder: public
Server config: settings/config.toml
Port: 8080
Force HTTPS: enabled
CDN cache: enabled
Health check: GET / expects 200
```

If connecting GitHub auto-deploy, choose:

```yaml
Repository: aims-rebuild
Production branch: main
App config file: app.yaml
```

For this project, local CLI deployment is the cleanest path because `public/` is generated by Hugo and is intentionally ignored by Git.
